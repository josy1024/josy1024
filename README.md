## Build the skateboard, not the Ferrari

**Problem:** I once built a cool improvement: technically clean, but the target group never used it because the value wasn't clear.

**What I changed:** Since then I start with the smallest thing that makes someone's work easier right away, and before building I ask: who will use it, and what changes for them tomorrow?

**Example:** The first version of our .NET middleware did one thing: it connected the ERP with the finance system and ended manual double entry (roughly 50 records a week, each with dozens of fields). Once that was running and trusted, I grew it step by step:
- data flowing in both directions: production data back to the ERP, finance back to the ERP, ERP to logistics
- a rebuilt legacy interface
- standardized, dynamic output formats
- stronger security

**Lesson:** A skateboard that someone actually rides beats a Ferrari sitting in the garage. Every extension had a user waiting for it, because the first small step had already proven its value.

## How I think
- **The Simple Josy Test:** How much needless, repetitive work is left? Can we see what's happening? What happens when something fails? Does it really help the business? → [IT architecture with Josy](ITArchitektur_mit_JOSY.MD)
- **The one IT question:** If we founded IT today, which 30% of our systems, processes and activities would we not do the same way again?
